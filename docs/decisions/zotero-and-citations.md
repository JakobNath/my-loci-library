# Decisions: Zotero, citations and exports

Moved word for word from `HOW_IT_WORKS.md` on 10 November 2026, in their original order (oldest first). Add new decisions on this topic at the end, in the same form: a bold title with the date, then the choice and the reason.

- **Exports (2026-11-10).** Settings › Export saves the whole catalog as CSV (one row per copy, every book owned or not, with the original date as written), JSON (every record as stored, shaped like catalog.json), CSL-JSON (one item per edition, with `original-date`) or BibTeX. BibTeX uses biblatex fields so the original date can be kept as `origdate`; keys are the first author's surname and the year (`augustine1991`), or the first word of the title when there is no author, with a, b, c added to repeats. biblatex counts years before Christ astronomically, so 399 BC is written -0398. The export code (`core/exports.js`) loads only when an export is chosen, and the file is saved by the browser's own download (`ui/save-file.js`); nothing leaves the device.
- **Zotero through its web API (2026-11-10).** PLAN.md asks for Zotero's local connection first and the web API as a fallback. Zotero 7's local API only reads, and the connector endpoint only adds new items to whatever collection is selected, so neither can update a book. The companion therefore writes through the web API with a key kept in the laptop's `config.json`; Zotero on the laptop shows the changes after its own sync. Build step 4.3 (proving local writes) is answered by this.
- **What goes where in a Zotero item (2026-11-10).** The original date and the pinned Better BibTeX key go in Extra ("Original Date:", "Citation Key:"), where Zotero and Better BibTeX read them; any other line in Extra is kept. The shelf location goes in "Loc. in Archive" and the permanent Loci link in URL, so a note in Obsidian that links to the Zotero item can reach both. Book sections carry the anthology's title as "Book Title" and are related to the anthology's item.
- **Citation keys (2026-11-10).** Keys follow Jakob's Better BibTeX pattern, the first author's surname (else the first editor's, else the title's first word) and the edition year, with a, b, c added for repeats (`citationKeyBase` in `core/zotero.js`, also used by the BibTeX export). A key is given once and kept in `integrations/zotero-links.json`; a book already in Zotero with a pinned key keeps that key. Keys of Zotero items that are not in Loci and not pinned cannot be seen through the web API, so a clash with one of those is possible; Better BibTeX warns about duplicate keys if it happens.
- **Zotero items deleted by hand come back (2026-11-10).** In the first live trial the Zotero items were deleted in Zotero, and the next run sent nothing, because the companion remembered them as sent. Each run now checks, with two small requests, that its collection exists (making it again if not) and which of its items still exist (`?format=versions`, not counting Zotero's trash); a missing item is sent again under the same pinned citation key. The link file is also saved after every batch, so a run stopped part-way (a window closed early) keeps what it already sent, and the command prints each stage as it goes.
- **The first Zotero trial changed a real item (2026-11-10).** On a first run the companion linked books already in Zotero instead of adding them again. In the trial into "Loci test" it matched the four Chemnitz *Enchiridion* items of the test catalog (the book and its three sections) to Jakob's own *Loci theologici 1*, because that item's ISBN field holds two ISBNs and only the last was read, and it wrote over it four times. No other item was touched (checked against Zotero's own backup, zotero.sqlite.bak). The item was put back exactly from that backup with the Zotero web API, with Jakob's agreement, and the trial's link file was removed from the test data. Since then: a run into any collection other than "My Loci Library" never links or changes an item that was already in Zotero; a first-run link needs a book (never a section) with an ISBN in common (every ISBN in the field is read) and an agreeing title, and each Zotero item is linked to one Loci book at most; an item's type is never changed; Zotero 7's own Citation Key field is read; and a full copy of every existing item is saved on the laptop (`my-loci-library-to-zotero/before/`) before it is first changed.
- **Only bibliographic data in Zotero's fields (2026-11-10, replaces "What goes where in a Zotero item").** Jakob checked a trial item against the needs of exact citations. Zotero's Chicago style (`chicago-notes-bibliography.csl`) prints URL and Loc. in Archive for books as well as archives, so the Loci link and the shelf would have appeared in every citation; and Better BibTeX may export Extra lines it does not know as a `note`. Zotero 7 has its own Original Date and Citation Key fields, so the original date ("397", or "385 BC", which Zotero keeps and Chicago prints as written) and the pinned key now go there, and URL, Loc. in Archive and Extra are left empty (lines the first version wrote in Extra are removed). The Loci link is a link attached under each book (Zotero's "linked URL" attachment), titled "My Loci Library · <shelf>" and renamed when the shelf changes; it appears in Zotero's item list but in no citation or export. Chosen by Jakob over putting the shelf in Call Number, which would have replaced the Library of Congress call numbers already on his books.
- **No Zotero sections for Bibles (2026-11-10).** After looking at how each kind of collection is cited (Chicago and the SBL Handbook cite scripture by book, chapter and verse in the text or notes, and an edition such as NA28 as a whole book; treatises in collected works, Church Fathers in ANF/NPNF, classical texts in the Loeb and documents of the Book of Concord are cited as works within a volume), Jakob chose sections for every anthology except Bibles. A book counts as a Bible when one of its works is in the category "Bibles", Logos calls it a Bible, or at least half of its works are books of the Bible (`isBible`, now in `core/bible.js`, so adding books and `loci-enrich` use the same rule); categories alone were not enough, since the test catalog files NA28's books under "Biblical studies". In the test catalog this picks out NA28 and the Holy Bible and nothing else.
- **Premodern names, and no original date for a collection (2026-11-10).** The second Zotero trial showed "Ignatius of Antioch" split as "Antioch, Ignatius of", and the Concordia Triglotta given the original date of its oldest piece ("orig. 301"). Chicago lists ancient and medieval writers by their whole name, and a collection has no single original date. In `core/zotero.js` (used by Zotero, the CSL-JSON export and BibTeX): a name with a joining word (of, à, the) or a customary epithet (Martyr, Chrysostom, and a few more) is kept whole, as is any name whose sort form has no comma, which lets a person settle any other case; and only a book holding one work gets an original date, so an anthology's works carry their own in their sections.
- **Collections by many authors, and volumes of a set (2026-11-10).** The third Zotero trial showed Holmes's *Apostolic Fathers* with Clement, Ignatius, Polycarp, Papias and Quadratus as its authors, and an ANF section whose book title ran together as "The Ante-Nicene Fathers: Volume 1: The Apostolic Fathers…". Chicago cites a collection of many authors under its editors, and a volume of a set as "*volume title*, vol. 1 of *set*". In `core/zotero.js` (Zotero, CSL-JSON and BibTeX alike): a collection names as authors only those every work shares (Plato for his dialogues), and an edition with a set and a volume number takes the set as its title, the volume number, and its own title as CSL's `volume-title` (in BibTeX, `maintitle` and `title`). Zotero has no field for a volume's own title; Zotero's Chicago style reads it from a `volume-title:` line in Extra, the one line the companion writes there.
- **A section carries its volume's translators and edition (2026-11-10).** A Chicago note copied from Zotero showed "Letters of Ignatius" in Holmes's *Apostolic Fathers* as "ed. Michael W. Holmes", without "and trans." or "3rd ed.". Each section now has the volume's translators (unless the work has a translator of its own) and its edition statement, and Zotero's Chicago style writes "ed. and trans." when one person is both.
- **Edition statements in citations (2026-11-10).** Zotero's Chicago style prints a numeric edition as "3rd ed." but prints words as they stand, so "3rd edition" appeared in a note. `editionForCitation` in `core/zotero.js` sends a plain ordinal as a number ("3rd edition" and "Third edition" become "3") and abbreviates the rest as Chicago does ("28th revised edition" becomes "28th rev. ed."); Zotero, CSL-JSON and BibTeX all use it. Loci itself keeps the statement as typed. With an original date present, Chicago's 18th edition puts the edition inside the parentheses as publication history, which is why it appears there.
- **Anonymous pieces keep their sections (2026-11-10).** Zotero's Chicago style puts a book's editor first when a section has no author ("F. Bente, ed., 'The Apostles' Creed,' in Concordia Triglotta…"), where Chicago begins with the title; it is a reported, unfixed issue in that style. Jakob chose to keep sections for anonymous pieces (the creeds, the Didache, the Epistle to Diognetus, the Shepherd of Hermas) so the data stays exact, and to correct the order by hand when citing one; if Zotero fixes the style, those notes come right by themselves. Pieces with a traditional author cite correctly once Loci records that author (Melanchthon for the Augsburg Confession and the Apology, Luther for the Smalcald Articles and the catechisms).
- **Sections only for works marked to cite (2026-11-11, Jakob; not yet built).** Every work inside an anthology is sent to Zotero as a section today. With every story, poem and sermon now to be recorded, a Library of America volume alone would add about 120 items, keyed Poe1984a to Poe1984dp, crowding the Zotero picker, and a work later removed from a book's contents would stay in Zotero for good as "Loci: removed", since Loci never deletes there. Jakob chose: books are always sent; a work inside a book is sent as a section only when "Cite this work" is tapped for it in Loci. Its citekey still follows his Better BibTeX pattern. This touches the Zotero companion, so it waits for Jakob's go-ahead, and should be built before his first real Zotero run.
- **Uncertain original dates (2026-11-12, decided without Jakob at his request).** Until now a work's sort year went to Zotero's Original Date field, so "c. 397–400" was cited as "orig. 397" and "early 2nd c." as "orig. 101": a precision the dating does not claim. What the fields expect: the Chicago Manual allows "ca." and a bracketed "[1750?]" for uncertain publication dates (14.44, 14.127, 14.145, as quoted on the Zotero forums; not checked against the Manual itself); the SBL Handbook writes "ca." (not "c.") and BCE/CE; and *Journal of Early Christian Studies*, *Vigiliae Christianae* and *Classical Quarterly* cite ancient texts by work and section, with no date of composition in the note. Zotero's side (its source code, read 12 November 2026): older versions read "ca. 397" as the year 397 and keep the rest as a stray word; the newest code (August 2026) reads EDTF dates ("0397~"), and its Chicago 18 style then prints "[397?]", which in Chicago means a guessed printing date, not "about 397"; no released Zotero style prints "ca." there. A journal editor in these fields would rather see no original date than a false one, so: **only an exact year is sent to Zotero** ("1689", "385 BC"); a circa date, a span, a century or an open date is not sent, and the field is then left as it is in Zotero, so a person may type "ca. 397" there by hand. The date stays in Loci, to be written into the prose ("written ca. 397–400"). The CSL-JSON and BibTeX exports, read by other programs, now say exactly what the dating says (`originalDateOf` in `core/zotero.js`): a year, a span of two years, and a circa flag (biblatex `origdate = {0397~/0400~}`); a century or open date gives none. Look again if Zotero's Chicago styles learn to print "ca.".
- **Books only, no sections (2026-11-13, Jakob; replaces "Sections only for works marked to cite"; built in the tools the same day).** Looking at how he actually cites: a book is cited as a whole with the page given in Zotero's citation box; ancient and patristic texts by work and section (Plato, *Phaedo* 64a), with the edition used listed once as a book; Luther's Works and the Book of Concord by abbreviation and volume (LW 31:343, Ap IV.5), each volume one book item. Only a chapter by another author in an edited volume needs a Zotero "book section", and that is rare. Jakob judged a "Cite this work" box in Loci more work than adjusting the odd footnote by hand. So the companion sends one item per book and no sections at all; when a chapter is needed, it is made by hand in Zotero (right-click the book, "Create Book Section"; in Zotero 7 this leaves the chapter's title and author empty and may put the book's title in Title rather than Book Title, so both are fixed by hand), and the companion never touches items it did not make. Sections sent by earlier versions (the trials) are tagged "Loci: removed", never deleted. Obsidian is not affected: it names each note by citekey and reads the rest from Zotero, and a pinned citekey never changes. The format-3 `cite` field on contents entries stays in the records, unused, so no format change is needed. Bibles were already sent as one book; that now holds for every book.
- **The set's short form is not sent to Zotero (2026-11-13, Jakob).** A set's short form (LW, AE) is kept in Loci and searched there, but Zotero's book fields have no place for a series abbreviation (Short Title is the item's own short title), so "LW 31:343" cannot come out of Zotero by itself. Writing it into another field would put stray text into citations. The abbreviation is typed in the text or kept in an article's list of abbreviations.
- **Books already in Zotero are only filled, never overwritten (2026-11-13).** The first run used to link a book already in Zotero and replace its fields with Loci's, empty ones included, keeping a copy first. Jakob's Zotero library holds items he cites from, and a copy on disk is a poor undo. Now such a book is remembered as "adopted" in `zotero-links.json`, and on the first run and every later one only its empty fields are filled; each difference is listed in the report. Books the companion made itself are still kept in step with Loci. Rejected: asking about each difference, which is slow for a whole library.
- **Old sections, once tagged, are left alone (2026-11-13).** Building "Books only, no sections": every link in `zotero-links.json` for a section ("<edition id>/<work id>") is tagged "Loci: removed" once, whether its book is still held, gone, or no longer lists the work. A section deleted in Zotero is not sent again and not counted as missing; its link stays, keeping its citation key, so that key is never given to another item. The "related" mark earlier sections were given is left as it is. Reason: nothing is ever deleted from Zotero, and an old section may still be cited from Obsidian.
